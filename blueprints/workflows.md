# WFS CMMS — Workflow Blueprint  

## Complete Workflow Specification for Master Blueprint V2  

## Part of Hybrid Blueprint Structure

---

# 1. WORKFLOW OVERVIEW  

Workflows define how work moves through the CMMS.  

They are the backbone of the system and determine:

- how workorders are created  

- how diagnostics flow  

- how PM flows  

- how repairs flow  

- how drivers submit defects  

- how AIMI routes work  

- how scheduling works  

- how parts are used  

- how compliance is enforced  

- how telematics triggers actions  

All workflows plug into the **Workorder Lifecycle**, the central nervous system of the CMMS.

---

# 3. AIMI DIAGNOSTIC WORKFLOW  

The AIMI Diagnose Button triggers the diagnostic workflow.

## 3.1 Diagnostic Flow Steps  

1. **Symptom Intake**  

   - voice  

   - text  

   - telematics  

   - driver defect  

   - technician notes  

2. **Fault Correlation**  

   AIMI correlates symptoms with known patterns.

3. **Diagnostic Path Selection**  

   AIMI selects the fastest, most accurate path.

4. **Step‑by‑Step Troubleshooting**  

   - guided steps  

   - voice‑activated steps  

   - multilingual steps  

   - adaptive UI steps  

5. **Technician Learning Capture**  

   AIMI learns from technician behavior.

6. **Repair Recommendation**  

   AIMI recommends the most likely fix.

7. **Verification Steps**  

   AIMI ensures the repair actually solved the issue.

8. **Closeout Checklist**  

   AIMI generates a final checklist.
